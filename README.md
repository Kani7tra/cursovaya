# ИС «ГигаКузня» — веб-приложение, мобильное приложение и общий сервер

Информационная система кузнечной мастерской. В неё входят:
- **сайт** (React + TypeScript, Vite) для трёх ролей: заказчик, кузнец, администратор;
- **общий сервер (REST API)** на Node.js + PostgreSQL. Его же будет использовать мобильное приложение.

## Что нужно установить (один раз)
1. **Node.js 20 LTS или новее**: https://nodejs.org
2. **PostgreSQL 14+**: https://www.postgresql.org/download/. Запомните пароль пользователя `postgres`.

## Запуск
1. Откройте `server\.env.example`, скопируйте его в `server\.env` и укажите свой пароль PostgreSQL:
   `DATABASE_URL=postgres://postgres:ВАШ_ПАРОЛЬ@localhost:5432/gigakuznya`
   (если файла `.env` нет, `start.bat` создаст его сам с паролем `1234`).
2. Дважды щёлкните **`start.bat`**. Скрипт установит зависимости, соберёт сайт, создаст базу и таблицы (миграции) и запустит сервер.
3. Откройте в браузере **http://localhost:5000**.

Телефон или другой компьютер **в той же Wi-Fi-сети** открывает сайт по адресу, который сервер выводит при запуске, например `http://192.168.0.105:5000`.

### Ручной запуск (по шагам)
```
cd server
npm install
npm run migrate      # создать БД и таблицы (повторно ничего не ломает)
npm start            # сервер + сайт на порту 5000

cd web
npm install
npm run build        # собрать сайт (после изменений в web/src)
npm run dev          # режим разработки: http://localhost:5173
```
`npm run reset-db` (в папке server) удаляет все таблицы и создаёт их заново с демо-данными.

## Функции по ролям
**Заказчик:** регистрация и вход; каталог с поиском, фильтрами (тип, материал, цена, сезонные) и сортировкой; карточка изделия; избранное; оформление предзаказа (желаемая дата, комментарий, автоматическая скидка, списание баллов); отслеживание статуса и отмена нового предзаказа; личный кабинет (данные, смена пароля, баллы, история); сообщения кузнецу; отзывы (создание, редактирование, удаление).

**Кузнец:** добавление, редактирование и удаление изделий (фото хранится в БД); сезонные цены (период, активация); скидки (процентные и фиксированные, на изделие и/или заказчика, период, активация); обработка предзаказов (смена статуса, при этом заказчику уходит уведомление); заказчики и начисление баллов; аналитика спроса (избранное, предзаказы, статусы, выручка); сообщения.

**Администратор:** пользователи (создание, изменение, назначение ролей, блокировка, удаление, корректировка баллов); журнал событий и ошибок; доступ ко всем разделам кузнеца, удаление предзаказов и отзывов при сбоях.

**Общее:** шапка (название, навигация по роли, иконка профиля), подвал (навигация, контакты, форма письма администратору), адаптивная вёрстка (ПК, планшет, телефон), валидация всех форм на клиенте и на сервере.

## Формулы
- Действующая цена = активная сезонная цена на сегодня, а если её нет — базовая цена.
- Скидка: процентная = Цена × Размер / 100, фиксированная = Размер. Применяется самая выгодная из действующих.
- **Итог = (Цена − Скидка) × (1 − Баллы / 100)**, где списывается не более 30 баллов (1 балл = 1 %).
- Начисление при статусе «Отгружен»: **Баллы = ⌊Итог / 1000⌋ × 10**. При отмене списанные баллы возвращаются.

## Отличия от ER-модели и ТЗ (учесть в документации)
- Добавлена таблица **logs** (журнал событий и ошибок) для функции «Мониторинг».
- В **preorders** добавлены `final_price` (итоговая цена) и `points_used` (списанные баллы): без них нельзя применить и вернуть баллы.
- `users.password`: varchar(255), потому что хранится хэш scrypt, а не пароль.
- Сервер написан на **Node.js** вместо ASP.NET Core, мобильное приложение будет на **TypeScript** вместо Flutter (п. 4.5 ТЗ). Swagger не используется.
- Уведомления об изменении статуса и начислении баллов приходят заказчику в «Сообщения».
- Восстановление пароля по e-mail не реализовано (нужен почтовый сервер). Пароль сбрасывает администратор.

## Мобильное приложение (React Native + Expo, TypeScript)
Папка `mobile/`. Работает через тот же сервер, что и сайт.

**Запуск на телефоне:**
1. Установите на телефон приложение **Expo Go** (Google Play / App Store).
2. Подключите телефон и компьютер к **одной Wi-Fi сети**.
3. Запустите `start.bat` (сервер) и не закрывайте окно.
4. Запустите `start-mobile.bat`. Первый раз установка займёт несколько минут.
5. Отсканируйте QR-код из окна: на Android — внутри Expo Go, на iPhone — камерой.
6. Если приложение пишет «Нет связи с сервером», нажмите «⚙ Сервер» на экране входа и введите адрес из окна сервера (строка «в локальной сети»), например `http://192.168.0.105:5000`.

Если Windows спросит про брандмауэр для Node.js, разрешите доступ в **частных сетях**.

**Функции:** для заказчика — вход и регистрация, каталог с поиском и фильтрами (тип, материал, сезон), сортировка, карточка изделия, избранное, быстрый предзаказ с сохранёнными контактными данными и списанием баллов, отслеживание статуса и отмена, отзывы, сообщения кузнецу, личный кабинет; навигация через гамбургер-меню; уведомления о новых сообщениях и смене статуса (проверка каждые 15 секунд). Для кузнеца — удалённая обработка предзаказов (смена статуса, звонок и сообщение заказчику). Администратор работает через сайт.

Push-уведомления от системы телефона в Expo Go недоступны (нужна отдельная сборка приложения), поэтому уведомления показываются внутри приложения.
